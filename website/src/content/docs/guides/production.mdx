<Steps>

1. **Create a user and the secrets.** Keys are 32 random bytes as hex; `keygen` writes them with mode 0600 and never
   overwrites a file.

   ```bash
   sudo useradd --system --home /var/lib/k10s k10s
   sudo install -d -o k10s -g k10s -m 0700 /etc/k10s
   sudo -u k10s k10s keygen -o /etc/k10s/admin.key     # same file on every node you deploy to
   sudo -u k10s k10s keygen -o /etc/k10s/cluster.key   # same file on every node
   ```

2. **Install a systemd unit.** The node binds its ports, then confines itself; the unit adds its own layer.

   ```ini title="/etc/systemd/system/k10s.service"
   [Unit]
   Description=k10s node
   After=network-online.target
   Wants=network-online.target

   [Service]
   ExecStart=/usr/local/bin/k10s node --data /var/lib/k10s --http 0.0.0.0:8080 \
     --admin 10.0.0.1:8081 --admin-token-file /etc/k10s/admin.key \
     --cluster-key-file /etc/k10s/cluster.key --advertise 10.0.0.1 \
     --join 10.0.0.1:7946,10.0.0.2:7946,10.0.0.3:7946
   User=k10s
   StateDirectory=k10s
   NoNewPrivileges=yes
   ProtectSystem=strict
   ProtectHome=yes
   PrivateTmp=yes
   PrivateDevices=yes
   ProtectKernelTunables=yes
   ProtectKernelModules=yes
   ProtectControlGroups=yes
   RestrictAddressFamilies=AF_INET AF_INET6
   RestrictNamespaces=yes
   LockPersonality=yes
   # The JIT maps code RW then RX: leave MemoryDenyWriteExecute off.
   CapabilityBoundingSet=
   LimitNOFILE=65536

   [Install]
   WantedBy=multi-user.target
   ```

   For a port below 1024, set `CapabilityBoundingSet=CAP_NET_BIND_SERVICE` and
   `AmbientCapabilities=CAP_NET_BIND_SERVICE` instead.

3. **Start it and read what it applied.**

   <Terminal
   	session={`
   $ sudo systemctl enable --now k10s
   $ journalctl -u k10s -n 4 -o cat
   k10s: cluster key id 9c66ecc2b991cd9e
   k10s: sandbox mode=on user=998 caps=none landlock=abi2 seccomp=kill jit_dump=-
   k10s: admin API on http://10.0.0.1:8081: requests signed with the key in /etc/k10s/admin.key
   k10s 0.1.0+1a2b3c4: node \`node-1\` listening on http://0.0.0.0:8080 (8 shards, backend jit, data /var/lib/k10s)
   `}
   />

4. **Deploy from your machine** with a copy of the admin key (requests are signed with it; it never travels):

   ```bash
   k10s apply app.k10s --node 10.0.0.1:8081 --admin-token-file admin.key
   ```

   The CLI also reads `$K10S_ADMIN_TOKEN_FILE`. Signed requests carry a timestamp: keep node and client clocks
   within 60 s (NTP).

</Steps>

## Ports

| Port | Protocol | Who needs it |
|---|---|---|
| `--http` (8080) | TCP | clients of your services; `/_k10s/health` |
| `--admin` | TCP | operators and scrapers only |
| `--gossip` (7946) | UDP | other nodes |
| `--rpc` (7947) | TCP | other nodes |

## The process sandbox

`--sandbox on` (the default) applies, in order: close inherited descriptors and set `no_new_privs`, read the secrets
and bind every listener, drop to `--user` when started as root (root without `--user` is refused), drop every
capability, Landlock (files limited to the data directory, read-write, nothing executable), then a seccomp allowlist
of 96 syscalls. The stores, the last bundle and every thread start inside the sandbox. Anything outside the
allowlist kills the process: `execve`, `fork`, namespaces, `ptrace`, `mount`, `bpf`, `io_uring`, new listening
sockets, executable `mmap`; sockets other than IPv4/IPv6 stream or datagram are refused.

- Landlock is required: on a kernel without it the node does not start; `--sandbox seccomp-only` runs without it.
- `--sandbox log` helps find a missing syscall: no Landlock, and calls the filter would kill are logged by the kernel
  (`journalctl -k | grep type=1326`) and run; its errno rules still apply.
- `--sandbox off` disables Landlock and seccomp (`--user` still applies). Library users (`k10s run`, tests,
  benchmarks) get no sandbox.
- The hot-path syscalls take no argument checks, so the kernel's seccomp cache serves them: no measurable cost.

## Sizing

- `--mem` caps instance memory (default: physical RAM). Every placed service reserves one instance; size it for
  the reservations plus the bursts you expect, and watch `k10s_memory_refused_total`.
- `--shards` defaults to the available parallelism. `--pin` pins shards to cores.
- `--kv-max` (256 MiB) bounds each service's key-value data; `--conn-buffer-max` bounds HTTP buffering node-wide.

## What to back up

The data directory holds everything a node needs to restart: the applied bundle (`bundle.k10b`, or `manifest.k10m`
and `blobs/` in cluster mode), the key-value logs (`kv/`), and in cluster mode the node id, incarnation and known
peers. A replacement node with an empty directory joins and fetches the desired state from its peers; only the
node-local key-value data is lost.

<Aside type="caution" title="No TLS yet">
	Neither the admin API nor the ingress speaks TLS. Signed admin requests cannot be forged or replayed, but their
	contents travel in clear: keep `--admin` on a private network, or put both behind a TLS proxy.
</Aside>
