k10s is one static binary: node daemon, JIT, Ten compiler and CLI. Prebuilt binaries are for x86-64 and arm64
(aarch64) Linux; on arm64, replace `x86_64` with `aarch64` in the commands below.

<Tabs syncKey="install">
<TabItem label="Prebuilt binary">

<Steps>

1. Download the static (musl) archive and the checksums of the latest release:

   ```bash
   gh release download --repo bzzdevlabs/k10s \
     --pattern 'k10s-*-x86_64-unknown-linux-musl.tar.gz' --pattern SHA256SUMS
   ```

   Or pick the files by hand on the [releases page](https://github.com/bzzdevlabs/k10s/releases).

2. Verify and unpack:

   ```bash
   sha256sum -c SHA256SUMS --ignore-missing
   tar xzf k10s-*-x86_64-unknown-linux-musl.tar.gz
   ```

3. Put `k10s` on your `PATH`:

   ```bash
   sudo install -m 0755 k10s-*-x86_64-unknown-linux-musl/k10s /usr/local/bin/k10s
   ```

</Steps>

</TabItem>
<TabItem label="From source">

<Steps>

1. Install a stable [Rust toolchain](https://rustup.rs) and clone the repository:

   ```bash
   git clone https://github.com/bzzdevlabs/k10s.git && cd k10s
   ```

2. Build the binary:

   ```bash
   cargo build --release -p k10s
   ```

3. The binary is `target/release/k10s`. Copy it anywhere: it has no runtime dependencies besides libc.

</Steps>

</TabItem>
</Tabs>

Check the installation:

<Terminal
	session={`
$ k10s --version
k10s 0.1.0+1a2b3c4
`}
/>

## Release archives

Every release publishes these files. `V` is the version (`0.1.0`, or `0.1.1-dev.45` for a development build).

| Archive | Contents |
|---|---|
| `k10s-V-x86_64-unknown-linux-musl.tar.gz` | `k10s`, statically linked: runs on any x86-64 Linux |
| `k10s-V-x86_64-unknown-linux-gnu.tar.gz` | the same, linked against glibc |
| `k10s-V-aarch64-unknown-linux-musl.tar.gz` | `k10s` for arm64 Linux, statically linked (services run on the interpreter) |
| `k10s-examples-V.tar.gz` | Ten sources, compiled `.k10` modules and `app.k10s` |
| `k10s-metal-V-x86_64.tar.gz` | the [bare-metal kernel](/k10s/guides/bare-metal/) and its bundle tool |
| `k10s-os-V-x86_64-vm.img.xz` | a [disk image](/k10s/guides/bare-metal/#on-a-linux-kernel-pid-1-mode) with `k10s` as the only program of a Linux kernel, for VMs and clouds (BIOS and UEFI) |
| `k10s-os-V-x86_64-metal.img.xz` | the same for PCs and servers: signed driver modules, NIC firmware |
| `k10s-os-V-x86_64-{vm,metal}.efi` | the signed boot files (UKIs) of these images: [OS updates](/k10s/guides/bare-metal/#updating-the-image) of running machines, PXE or another UEFI loader |
| `k10s-os-V-aarch64-vm.img.xz`, `k10s-os-V-aarch64-vm.efi` | the arm64 image for UEFI VMs and clouds, and its signed UKI |
| `k10s-os-V-aarch64-pi.img.xz`, `k10s-os-V-aarch64-pi.fat` | the Raspberry Pi 4 and 5 image, and its signed boot slot (OS updates) |
| `k10s-bench-V-linux-amd64.tar.gz` | benchmark workloads and the load generator |
| `k10s-V-src.tar.gz` | the sources, stamped with their version |
| `SHA256SUMS` | checksums of all of the above |

*Latest* on GitHub is the last stable release. Every push to `main` also publishes a development pre-release; see
[Releases and versions](/k10s/project/releases/).

## Requirements

- **x86-64 Linux** for the JIT. On arm64 (and any other architecture) services run on the reference interpreter,
  the default there; an arm64 JIT is planned.
- **Process sandbox:** `k10s node` confines itself with Landlock (Linux 5.13+, `landlock` in the kernel's LSM list)
  and seccomp, and logs what it applied at start-up; on a kernel without Landlock, run it with
  `--sandbox seccomp-only`. See [Production setup](/k10s/guides/production/).

<Aside>
	Nothing else is needed on a node: no container runtime, no CNI plugin, no etcd. The same binary is the CLI you
	use from your laptop.
</Aside>

## As the operating system

A node needs no Linux distribution either: write a release's disk image to a machine and `k10s` is the only program
(PID 1) on top of a Linux kernel used as a driver layer, or the runtime boots as its own kernel. See
[Bare metal](/k10s/guides/bare-metal/).
