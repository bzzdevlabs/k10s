This page runs one node on your machine, deploys the eight example services of the repository and calls them.
You need the `k10s` binary ([Installation](/k10s/start/installation/)) and a checkout of the repository for
`examples/`.

<Steps>

1. **Start a node.** It listens for HTTP on `127.0.0.1:8080` and keeps its state in the data directory.

   <Terminal
   	title="node"
   	session={`
   $ k10s node --http 127.0.0.1:8080 --data /tmp/k10s-data
   «dim:k10s: sandbox mode=on user=1000 caps=none landlock=abi2 seccomp=kill jit_dump=-»
   «dim:k10s: generated the admin key /tmp/k10s-data/admin.key»
   «dim:k10s: admin API on the ingress: requests signed with the key in /tmp/k10s-data/admin.key»
   k10s 0.1.0: node \`laptop\` listening on «teal:http://127.0.0.1:8080» (8 shards, backend jit, data /tmp/k10s-data)
   `}
   />

2. **Deploy.** In another terminal, point the CLI at the node's admin key and apply the manifest. The CLI compiles
   every `.ten` file it references and sends one bundle; the node validates and JIT-compiles every module before it
   switches over.

   <Terminal
   	session={`
   $ export K10S_ADMIN_TOKEN_FILE=/tmp/k10s-data/admin.key
   $ k10s apply examples/app.k10s
   {"ok":true,"version":1,"added":["chain","compute","counter","echo","hello","nbody","sort","todo"],
    "updated":[],"removed":[],"unchanged":[],"warnings":[]}
   `}
   />

3. **Call the services.** Every node routes `/<service>/<rest>` to a service.

   <Terminal
   	session={`
   $ curl 127.0.0.1:8080/hello/
   hello
   $ curl '127.0.0.1:8080/compute/?n=1000'
   cc2cbdc008d39ef7d46c8f4bd213c400cf60059acb1f0b409f7116b2912f2c9a
   $ curl 127.0.0.1:8080/chain/
   hello
   $ curl -X POST 127.0.0.1:8080/counter/ && curl -X POST 127.0.0.1:8080/counter/
   1
   2
   $ curl --data 'ship the docs' 127.0.0.1:8080/todo/
   {"id":1,"title":"ship the docs"}
   `}
   />

   `compute` runs a chain of SHA-256 hashes, `chain` calls `echo` through the host API, and `counter` and `todo`
   keep durable state in the node's key-value store: restart the node and they continue where they were.

4. **Look inside.** `status` reports every service, its instances, memory and counters as JSON.

   <Terminal
   	session={`
   $ k10s status | jq -c '.services[] | {name, instances, requests, mem_used}'
   {"name":"chain","instances":{"live":1,"idle":1,"peak":1},"requests":1,"mem_used":69632}
   {"name":"compute","instances":{"live":1,"idle":1,"peak":1},"requests":1,"mem_used":69632}
   {"name":"counter","instances":{"live":1,"idle":1,"peak":1},"requests":2,"mem_used":69632}
   {"name":"echo","instances":{"live":1,"idle":1,"peak":1},"requests":1,"mem_used":1052672}
   {"name":"hello","instances":{"live":1,"idle":1,"peak":1},"requests":1,"mem_used":69632}
   {"name":"nbody","instances":{"live":0,"idle":0,"peak":0},"requests":0,"mem_used":0}
   {"name":"sort","instances":{"live":0,"idle":0,"peak":0},"requests":0,"mem_used":0}
   {"name":"todo","instances":{"live":1,"idle":1,"peak":1},"requests":1,"mem_used":1052672}
   `}
   />

   A service that has served nothing has no instance at all: `nbody` and `sort` show `"live": 0` and use no memory
   until their first request.

</Steps>

## Run one request without a node

`k10s run` compiles a file and runs a single request in-process. The response body goes to stdout, the status and
logs to stderr: it is the fastest edit-run loop.

<Terminal
	session={`
$ k10s run examples/echo.ten --method POST --body hi
hi«dim:k10s: HTTP 200 (2 bytes, 0.106 ms)»
`}
/>

<Aside type="note" title="Admin access">
	`apply`, `status` and `logs` use the node's admin API under `/_k10s/`, and every request is signed with the node's
	admin key: `DATA/admin.key` (created on first start), or the file given with `--admin-token-file`. The CLI reads
	`--admin-token-file`, `$K10S_ADMIN_TOKEN_FILE`, or `~/.local/state/k10s/admin.key` (where a node without `--data`
	keeps its key); see [Production setup](/k10s/guides/production/).
</Aside>
