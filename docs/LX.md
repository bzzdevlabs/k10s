# k10-lx: the Linux syscall plan

k10-lx is the Linux-ABI personality of the native kernel that runs unmodified OCI images as ring-3 processes
(docs/research/oci.md §2–§4). This document is its specification: every x86-64 syscall with its status in the
milestones of oci.md §14, the argument subsets, the synthetic files and the errno of every refusal. The evidence
table and the per-call table are generated by `bench/oci/table.py` from `bench/oci/lxplan.py` (the plan) and
`bench/oci/syscalls.json` (the evidence); `table.py --check` (CI) fails when either drifts or when an M1 corpus image
makes a call the plan does not cover.

## Evidence

`bench/oci/trace.sh` traces a corpus of public images pinned by digest, each under its own entrypoint and command
with a realistic workload (start, requests, graceful stop by the image's stop signal), in a QEMU/KVM guest booted
from the pinned Debian 6.12 kernel (`os/debian-kernel.sh`); the image's merged layers are the guest's initramfs and
`lxtrace` (bench/oci/lxtrace, a ptrace tracer of our own) is its `/init`, which mounts what a container runtime
provides (proc, sys with cgroup2, dev with pts, shm and mqueue, generated `/etc/hosts`, `/etc/hostname`,
`/etc/resolv.conf`), follows every process and thread of the container and records calls, errnos, flag arguments,
the /proc, /sys, /dev and /etc paths named and the signals delivered. `bench/oci/elfscan.py` adds the static upper
bound: syscall wrappers imported by the traced programs and their libraries, by every ELF object of the image, and
`mov $nr,%eax; syscall` sites in static binaries. Results: `bench/oci/syscalls.md`.

Findings that shape the personality:
- No image calls `clock_gettime`, `gettimeofday` or `time`: they go through the vDSO, which M1 provides.
- `ioctl` is almost only `TCGETS`/`TIOCGWINSZ` on pipes and files (isatty; container stdio is a pipe): ENOTTY on a
  fast path. The others are FIONBIO, FIOASYNC and the SIOCGIF* family (the JVM's NetworkInterface).
- glibc 2.34+ threads and `posix_spawn` use `clone3` and fall back to `clone` on ENOSYS; every glibc process
  registers `rseq` and continues without it on ENOSYS. The fork shapes seen are plain fork (`SIGCHLD`, redis BGSAVE,
  nginx workers, busybox's `fork`), `vfork` (dash) and threads.
- libuv (node) and redis probe `io_uring_setup`; refused with EPERM as under Docker's default seccomp profile, they
  use epoll and threads. nginx probes `io_setup` (file AIO) and serves without it on ENOSYS.
- Go's net package, glibc's `getaddrinfo(AI_ADDRCONFIG)` and Python open `AF_NETLINK` raw sockets
  (`NETLINK_ROUTE`): the minimal RTM_GETLINK/GETADDR answer is M1.
- glibc 2.41 maps `MAP_DROPPABLE` memory only for a vDSO `getrandom`; the vDSO does not export one, so `getrandom`
  stays a syscall (7 of 9 images call it).
- `sed -i` copies ACLs with `fsetxattr(system.posix_acl_access)`: EOPNOTSUPP makes it fall back to `chmod`.
- Privilege-dropping entrypoints (setpriv, gosu) use `prctl` capability calls, `capget/capset`, `setgroups`,
  `setresuid/setresgid`; Go's `setuid` signals every thread (signal 33).
- Allocators and runtimes read `/proc/sys/vm/overcommit_memory` (redis, the JVM, Python, jemalloc in the Rust
  binary). k10-lx charges writable private memory at mmap and answers `2`; redis logs its overcommit warning and a
  BGSAVE fork needs the child's writable memory within the container's limit.
- glibc 2.42 (the temurin image's Ubuntu) places thread-stack guards with `MADV_GUARD_INSTALL` and falls back to
  `mprotect` on EINVAL.
- The JVM takes a SIGSEGV (implicit null checks, safepoints), reads cgroup v2 limits, `/proc/self/mountinfo` and
  `/proc/self/maps`, and sizes itself from `sched_getaffinity` and `/sys/devices/system/cpu`: M2.
- postgres uses SysV `shmget/shmat`, POSIX shm under `/dev/shm`, `sync_file_range`, `fallocate`, `pwritev` and
  `signalfd4`: M3 with the file layer of oci.md §7.5.

## Policy

- **M1** calls are implemented, partially where the table's note says so; **stub** calls return a documented fixed
  answer; **M2** and **M3** calls return ENOSYS until their milestone; **refused** calls return EPERM (the errno
  Docker's default seccomp profile returns, so images already handle it) or the errno in the note; every call
  missing from the plan returns ENOSYS.
- Refused and missing calls are counted per container and service with the call number in `/_k10s/status`, so a
  corpus run shows what to build next; the corpus gate (oci.md §13) pins these counters.
- Refused by policy (oci.md §0 out-of-scope list): mount and the mount API, `pivot_root`, `chroot`, `setns`,
  `unshare` of namespaces, `ptrace`, `process_vm_*`, `kcmp`, `pidfd_getfd`, `bpf`, `perf_event_open`, `io_uring_*`,
  `userfaultfd`, modules and `kexec_*`, `reboot`, `swapon/off`, `syslog`, the clock setters, `sethostname`,
  `setdomainname`, keyrings, quotas, `iopl/ioperm`, `modify_ldt`, NUMA page migration, fanotify, handles. 32-bit
  (ia32, x32) entry points are not provided. Protection keys answer as a CPU without PKU; `seccomp` and Landlock
  are ENOSYS (the personality is the filter); `clone3`, `rseq` and `futex_waitv` are ENOSYS by design (callers
  fall back).
- Credentials are the container's: uid 0 inside has no authority outside; `capset` and `PR_CAPBSET_DROP` only drop
  within the container's bounded set.

## Probes

`bench/oci/lxprobe` is the binary-level differential test of this plan (oci.md §13): 137 probes of the M1 calls
(processes, threads, exec, CoW memory and faults, signals with SA_RESTART/EINTR and alternate stacks, clocks and
timers, files and locks, pipes, epoll, eventfd/timerfd/signalfd, unix sockets with SCM_RIGHTS, TCP/UDP over IPv4
and IPv6, netlink through `getifaddrs`, /proc), each printed as `ok GROUP NAME` or `FAIL ...` with no pid, address,
port or time, so one binary's output under Linux and under k10s compares byte for byte. `scripts/oci-testimages.sh`
builds it static and dynamic against musl and packs it, the bench workloads and a busybox shell-script image as OCI
images; served by `os/tools/registry.py` and run by `bench/oci/trace.py --corpus bench/oci/testimages.json`, all
four run in the Linux guest, and both probe builds report no failure as root under Linux 6.12 and as a user under
the host's Linux, with identical output outside the root-only credential probes.
