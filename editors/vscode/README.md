# Ten & k10s for VS Code

Language support for [k10s](https://github.com/bzzdevlabs/k10s): **Ten** sources (`.ten`) and **k10s manifests**
(`.k10s`).

- **Syntax highlighting** for both languages (nested block comments, escapes, numeric literals, builtins, types,
  manifest keys and memory units).
- **Diagnostics as you type**, from the real k10s front ends compiled to WebAssembly (no k10s install needed):
  - Ten: the `k10-lang` compiler — syntax errors (several per run), unknown names with "did you mean", type
    mismatches with conversion hints, arity, missing returns, includes. Errors inside an included file are shown
    on that file. A file included by another open file is checked as part of that program, so it may use names the
    includer defines. Unsaved editor contents are used for included files.
  - k10s manifests: the `k10s apply` parser (keys, values, memory sizes, `calls` targets), plus each service's
    `code` file: it must exist, a `.ten` file must compile, a `.k10` file must be a valid TIR module.
- **File icons** in the Material style for `.ten` (the Ten logo, `docs/logo/ten.svg`) and `.k10s` (shown with
  file icon themes that have no icon of their own for these languages, such as Seti).
- **Folder icons** for folders named `k10s`, `.k10s` and `ten` with
  [Material Icon Theme](https://marketplace.visualstudio.com/items?itemName=PKief.material-icon-theme). Only the
  active icon theme draws folders, so the extension cannot add them by itself: it asks once (when Material Icon Theme
  is active) to add them to `material-icon-theme.folders.associations` in your user settings, and keeps those
  entries pointing at the installed version after updates. Commands: **Ten & k10s: Add Folder Icons to Material
  Icon Theme** / **Remove Folder Icons from Material Icon Theme**. Your own associations for these names win.
- Comment toggling, bracket matching, auto-closing pairs and indentation.

## Settings

| Setting | Default | |
|---|---|---|
| `ten.validate` | `true` | Check Ten files as you type. |
| `k10s.validate` | `true` | Check manifests and their services' `code` files as you type. |

## Building

```bash
editors/vscode/build.sh
```

Needs Rust with the `wasm32-unknown-unknown` target and Node.js ≥ 18. It builds the checker
(`checker/`, a wasm32 build of `k10-lang`, `k10-mesh` and `k10-ir`), runs `test/checker.test.js` and writes
`dist/k10s-ten-<version>.vsix`. Install it with `code --install-extension dist/k10s-ten-0.1.0.vsix`.
Icons are generated by `icons/generate.py`.

CI (`.github/workflows/vscode.yml`) builds and tests the extension whenever it or the compiler crates it embeds
change, and uploads the `.vsix`. Pushing a `vscode-vX.Y.Z` tag on main (matching `package.json`) publishes it as a
GitHub release.
